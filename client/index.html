Sign in

Development sign-in. The platform owns the real staff session; this exchanges an email for one against the module's own session store, and only runs when DEV_LOGIN is switched on. The access token is a shared secret so that finding this URL is not by itself enough to get in — it is a holding position, not authentication.

The token is the DEV_LOGIN_TOKEN variable on this service. Other roles on the demo account, which each see a different console: pm@demo.test, office@demo.test, books@demo.test.
